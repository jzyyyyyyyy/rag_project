## 第4页：项目背景

**【页面标题】**
一、项目背景——大语言模型的局限性

**【正文内容】**

大语言模型（LLM）虽然能力强大，但存在两个核心问题：

**❌ 知识截止问题**
- 模型知识来源于训练数据，训练完成后知识固定
- 无法回答训练截止日期之后的时效性问题
- 例："2024年巴黎奥运会女单网球冠军是谁？"

**❌ 幻觉问题（Hallucination）**
- 面对未知问题时，模型会编造看似合理但错误的答案
- 回答缺乏事实依据，难以信任
- 例：虚构人物背景、捏造数据来源

**两种解决方案对比：**

| 方案 | 优点 | 缺点 |
|------|------|------|
| 模型微调 | 提升领域适应性、增强意图理解 | 数据成本高、时效性差、技术门槛高 |
| **RAG本地知识库** | **无需训练、更新快、可溯源、成本低** | 依赖检索质量 |

**【演讲备注】**
首先看项目背景。大语言模型有两个固有的局限性：一是知识截止，训练完之后知识就固定了，没法回答新问题；二是幻觉，不知道的问题它会瞎编。解决这两个问题主要有微调和RAG两种方案，微调成本高、更新慢，而RAG不需要重新训练模型，只要更新知识库就行，所以我们选择了RAG方案。

## 第5页：项目意义

**【页面标题】**
一、项目背景——RAG 技术的价值

**【正文内容】**

**什么是 RAG？**
检索增强生成（Retrieval-Augmented Generation）：在生成答案前，先从外部知识库检索相关信息，再结合大模型生成回答。

**RAG 的四大核心优势：**

| 优势 | 说明 |
|------|------|
| 🔒 保护数据隐私 | 业务知识保存在本地，无需上传训练，减少泄露风险 |
| 🎯 减少模型幻觉 | 回答基于真实检索内容，大幅降低胡说八道概率 |
| ⚡ 实时知识补充 | 知识库随时更新，回答能结合最新知识 |
| 💰 无需重新训练 | 不用微调大模型，只需更新知识库，成本低速度快 |

**本项目意义：**
- 完整复现 RAG 全流程，深入理解检索增强生成原理
- 实现可直接使用的知识库问答工具，应用于课程答疑、文档检索等场景
- 为同类大模型应用项目提供可参考的工程化案例

**【演讲备注】**
RAG就是检索增强生成，核心思想是先从知识库找相关内容，再让大模型基于这些内容回答。它有四个优势：保护隐私、减少幻觉、知识实时更新、不需要重新训练。我们做这个项目，一方面是实践课程学到的RAG技术，另一方面也是做一个真正能用的知识库问答工具。

## 第6页：RAG 工作流程

**【页面标题】**
二、RAG 技术原理——完整工作流程

**【正文内容】**

RAG 分为**离线建库**和**在线问答**两个阶段：

**🔧 离线建库阶段（一次性）**
1. 文档预处理：加载 PDF/Word/TXT 等文档
2. 文本分段：将长文档切成语义独立的小块（Chunk）
3. 文本向量化：用嵌入模型将每个块转为语义向量
4. 向量存储：向量 + 原文存入向量数据库

**💬 在线问答阶段（每次提问）**
5. 查询向量化：用户问题用同一个嵌入模型转成向量
6. 相似度检索：在向量库中找最相似的 Top-K 个片段
7. Prompt 拼接：检索片段 + 用户问题组合成 Prompt
8. 大模型生成：DeepSeek 基于检索内容生成答案
9. 结果返回：返回答案 + 引用来源，可溯源核实

**【演讲备注】**
RAG的完整流程分两个阶段。离线建库是一次性的，把文档读进来、切成小块、转成向量、存进数据库。在线问答是每次提问时做的：把问题也转成向量，在数据库里找最相关的几个片段，和问题拼在一起给大模型，大模型基于这些内容生成答案，同时返回来源。整个过程就像"开卷考试"，大模型可以参考资料再答题。

## 第7页：关键技术1——数据分段

**【页面标题】**
三、关键技术详解——数据分段（Chunking）

**【正文内容】**

**为什么要分段？**
- 大模型有上下文长度限制，放不下整本书
- 整篇文档向量被无关内容稀释，检索不准
- 分段后只取最相关的片段，精准且高效

**分段的核心权衡：**
> 在"保持语义完整性"和"便于精准检索"之间找平衡
> - 块过大 → 包含多主题，引入噪声
> - 块过小 → 割裂关键信息，上下文不足

**四种基础切分方法：**

| 方法 | 原理 | 适用场景 |
|------|------|----------|
| 固定大小分块 | 按字符数简单切割 | 日志等结构简单文档 |
| 按分隔符分块 | 按段落/标题/句号分割 | Markdown、代码等结构清晰文档 |
| 滑动窗口分块 | 固定大小 + 重叠区，避免边界丢失 | 通用文本改进方案 |
| **多层递归分块** | 先大分隔符，太大再用小分隔符递归切 | **PDF等复杂文档（本项目采用）** |

**本项目参数：** chunk_size=500字符，chunk_overlap=80字符，中文优化分隔符

**【演讲备注】**
第一个关键技术是数据分段。因为大模型放不下整本书，而且整篇文档的向量会被无关内容稀释，所以必须把长文档切成小块。分段的核心是平衡语义完整和检索精度，块太大有噪声，块太小信息不全。我们用的是多层递归分块，优先按段落和句号切，500字符一块，重叠80字符，这是课件里推荐的中文优化方案。

## 第8页：关键技术2——嵌入模型

**【页面标题】**
三、关键技术详解——嵌入模型（Embedding）

**【正文内容】**

**什么是嵌入？**
将文本字符串转换为固定长度的数值向量，用向量表示语义。
- 语义相近的文本 → 向量距离近
- 语义不同的文本 → 向量距离远

**嵌入模型 vs 大语言模型：**

| 维度 | 嵌入模型 | 大语言模型 |
|------|----------|------------|
| 目标 | 生成代表语义的固定向量 | 生成文本 |
| 架构 | 编码器（BERT类） | 解码器（GPT类） |
| 输出 | 一个向量（如768维） | 一段文本 |
| 用途 | 语义检索、相似度计算 | 对话、写作、生成 |

**本项目选型：text2vec-base-chinese**
- 开源中文语义向量模型，基于 BERT 架构
- 输出 768 维向量，本地运行，数据不出本机
- 专门针对中文优化，语义表征质量高
- 配置：CPU 运行，向量 L2 归一化（余弦相似度更准）

**【演讲备注】**
第二个关键技术是嵌入模型。嵌入就是把文字变成一串数字向量，语义相近的文字向量距离就近，这样就能用数学计算来做语义匹配。嵌入模型和大语言模型不一样，它是编码器架构，输出一个固定长度的向量，专门用来做语义检索；而大模型是解码器架构，用来生成文本。我们用的是text2vec-base-chinese这个中文开源模型，本地运行，保护隐私。

## 第9页：关键技术3——向量数据库

**【页面标题】**
三、关键技术详解——向量数据库与检索

**【正文内容】**

**向量数据库是什么？**
专为存储和检索高维向量设计的数据库，通过相似度计算实现语义搜索。

**三种检索策略：**

| 策略 | 原理 | 特点 |
|------|------|------|
| 关键词检索 | 全文匹配关键词 | 快但无法处理语义关联 |
| **向量语义检索** | 计算向量距离找相似内容 | **能理解语义，跨语言匹配（本项目采用）** |
| 混合检索 | 关键词 + 语义加权 | 效果最好但更复杂 |

**核心技术：**
- **相似度计算**：余弦相似度，计算向量夹角
- **ANN 近似最近邻**：避免暴力遍历，毫秒级检索
  - IVF：聚类分簇，先找簇再搜内部
  - HNSW：多层图结构，从顶层快速跳跃到底层

**本项目选型：Chroma**
- 轻量级本地向量库，无需部署服务
- 与 LangChain 无缝集成，Python 接口简洁
- 支持持久化存储、余弦相似度检索、元数据过滤

**【演讲备注】**
第三个关键技术是向量数据库。它专门存向量，通过相似度计算做语义搜索。检索策略有关键词、向量语义和混合三种，我们用的是向量语义检索，这样即使用户的用词和文档不一样，也能找到语义相关的内容。为了快，向量库用ANN近似最近邻算法，比如IVF和HNSW，牺牲一点点精度换来百倍速度。我们选的是Chroma，轻量级本地数据库，不用装服务，和LangChain集成很好。

## 第12页：在线问答模块实现

**【页面标题】**
四、系统设计与实现——在线问答模块

**【正文内容】**

对应代码文件：`chat.py` / `app.py`

**核心：RetrievalQA 问答链**
```python
# 1. 加载向量库，转为检索器
db = Chroma(persist_directory="./vector_db", embedding_function=embeddings)
retriever = db.as_retriever(search_kwargs={"k": 3})

# 2. 初始化 DeepSeek 大模型
llm = ChatOpenAI(api_key="xxx", base_url="https://api.deepseek.com/v1",
                 model="deepseek-chat", temperature=0.3)

# 3. RAG 专用 Prompt（强制基于原文回答，减少幻觉）
prompt = """你是专业的文档问答助手。请严格根据【参考资料】回答。
如果资料中没有答案，直接说"无法回答"，不要编造。
【参考资料】{context}
【用户问题】{question}"""

# 4. 组装问答链
qa_chain = RetrievalQA.from_chain_type(
    llm=llm, chain_type="stuff", retriever=retriever,
    return_source_documents=True, chain_type_kwargs={"prompt": PROMPT},
)

# 5. 调用问答
result = qa_chain.invoke("RAG的全称是什么？")
```

**关键设计：**
- `temperature=0.3`：低随机性，回答更严谨
- `return_source_documents=True`：返回引用原文，可溯源
- Prompt 明确约束"无答案则拒绝回答"，有效防幻觉

**【演讲备注】**
在线问答模块的核心是LangChain的RetrievalQA链。首先加载Chroma向量库，转成检索器，返回最相关的3个片段。然后用ChatOpenAI调用DeepSeek，温度设0.3让回答更严谨。最重要的是Prompt设计，我们明确要求模型只根据参考资料回答，没有答案就说无法回答，这是防幻觉的关键。最后组装成RetrievalQA链，调用invoke就能得到答案和来源。

## 第16页：参数对比实验

**【页面标题】**
五、实验测试与结果分析——参数对比实验

**【正文内容】**

**实验一：不同分块大小（chunk_size）的影响**

| chunk_size | 分块数 | 检索精度 | 回答完整性 | 评价 |
|------------|--------|----------|------------|------|
| 200 | 550 | 高 | 低（信息不足） | 上下文不够 |
| **500** | **220** | **较高** | **高** | **✅ 平衡最佳** |
| 800 | 140 | 中 | 高 | 引入噪声 |
| 1500 | 75 | 低 | 较高 | 稀释严重 |

**实验二：不同检索数量（top_k）的影响**

| top_k | 回答准确度 | 推理速度 | 评价 |
|-------|------------|----------|------|
| 1 | 较低 | 快 | 信息不全 |
| **3** | **高** | **较快** | **✅ 推荐配置** |
| 5 | 高 | 中等 | 信息冗余 |
| 10 | 中 | 慢 | 噪声过多 |

**结论：** 最优参数为 chunk_size=500，top_k=3，与课件建议一致。

**【演讲备注】**
我们还做了两组参数对比实验。第一组测不同分块大小，发现200太小信息不够，800以上又有噪声，500的时候平衡最好。第二组测检索数量，1个不够，5个以上有冗余，3个效果最好。所以最终我们用的是chunk_size=500、top_k=3，这也和课件里的建议一致。
